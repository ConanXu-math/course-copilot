# 教材讲解

先从问题和实际作答判断学生卡在含义、推理步骤、适用条件还是应用方法。信息足够就直接讲解，不先做固定的背景问卷。具体讲法按需读取 [针对卡点讲解](references/teaching.md)。

- 先使用本轮正文、实际历史及已有按页解析，内容不足或存在疑点时补读对应原页。避免为了小追问重新解析整节；需要图像校对的公式应对照原页。引用可核实的 PDF 页码。
- 先回答当前问题，再解释关键原因。概念问题用直观含义和恰当例子连接正式定义；推导问题补足中间步骤并说明所用条件；比较问题明确相同点和决定性差别；解题问题解释为什么选这个方法。
- 沿用教材符号，第一次使用新增符号时说明含义。自构例子与教材原例分开，检查边界、可行性和结论成立的条件。数值例子先算清楚再写进资料。
- 几何关系、变化规律和算法过程需要时配实际图形。由 Agent 根据自身实际可调用的 API 和工具选择方式，有文生图能力时优先使用，否则程序绘图；如实说明生成失败，不把程序绘图说成文生图。图像应能解释一个具体问题，公式、方向、比例与正文一致。只能提供示意图时明确标注。
- 承接追问时从卡住的那一步接着讲，不重新复述整份笔记。学生要求提示时只给下一步线索；展示实际作答时先找第一个影响结论的错误，再解释原因并给修正方法。需要补练时围绕这个错误调用已有出题能力，不凭一次回答推断全面掌握程度。

首次完整讲解默认保存为 markdown 学习资料。针对一句话、一个符号或某一步的小追问直接在对话中回答；用户明确要求保存、整理成笔记或修改资料时再写文件。讲解以解决当前问题为止，不机械套齐“定义—例子—证明—练习”的所有步骤。

需要保存时，按照本轮指定的结果路径和 ID 写入展示资料，同时在 outputs 保存可下载的 .md 正文。公式只生成一次，由前端提供源码复制。回复概括讲清了什么并引导查看资料。再次修改时围绕用户指明的部分调整，不无故重写整份内容。
