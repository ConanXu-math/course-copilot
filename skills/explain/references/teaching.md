# 针对卡点讲解

这些是按需选择的方法，不是每次回答必须执行的清单。

| 卡点 | 怎样讲 |
| --- | --- |
| 符号或维度 | 说明对象、已知量与待求量；用一个小维度例子检查乘法、转置、索引与结果的形状 |
| 定义抽象 | 给一个满足定义的例子，再给一个只差关键条件的反例，回到正式定义辨认差别 |
| 推导跳步 | 从学生指出的前一行开始，补出缺失变形，说明用了什么恒等式、定理或假设 |
| 条件必要性 | 区分充分、必要与技术性假设；去掉条件后给确实成立的反例，不能把证明暂时不会做说成结论一定不成立 |
| 证明没思路 | 先交代要证明什么、核心思路和关键工具，再展开需要补足的步骤 |
| 算法不会用 | 在同一个简单例子上手算一次更新，再解释一般公式及适用条件 |
| 方法容易混淆 | 围绕同一任务和同一组假设比较，而不是只列两个名称的独立介绍 |

公式出现前说明要计算什么；出现后解释各项意义和结论用途。例子沿用教材记号，不先另设一套符号再翻译回教材。用同一个例子连接直觉、公式、计算和结果，避免每段都更换背景。

回应作答时引用学生实际写出的步骤，指出最早的关键错误；后续由它造成的错误合并说明。正确的不同解法应认可，不能要求与参考答案的文字或形式完全相同。没有提供的步骤不按错误处理。

分级提示只推进一小步：先提示应关注的条件，再提示可用关系，最后按学生需要展开推导。学生明确要完整答案时直接给，不强制经历提示流程。是否配图依据当前理解困难和 Agent 实际能力决定。
